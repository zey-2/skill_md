What Is an AI Agent?

01 — AGENT RECAP

The Agent Formula

An AI agent is not just a chatbot. It is an LLM that can use tools in a loop to achieve a goal. It can act on the world.

The minimum components:

  • LLM — language model for reasoning
  • Tools — file ops, web search, code execution, APIs
  • Loop — multiple turns, not a single API call
  • Goals — what the agent is trying to achieve

01 — AGENT RECAP

The ReAct Loop

Unlike a single API call, an agent runs multiple turns in a cycle:

  • Reveal — What does the agent know right now?
  • Think — What should I do next?
  • Act — Call a tool (read file, search, run code)
  • Observe — What did the tool return?

The loop repeats until the goal is met or the agent decides it needs to stop.

What's the minimum difference between asking ChatGPT a question and running an agent?

02

What Is an Agent Skill?

Problem

Agents Are Inconsistent

The same agent will do a recurring task differently each time, because it has no packaged knowledge of how your team wants it done.

Solution

A Skill = Reusable Operating Procedure

A skill tells the agent:

  • When to use it
  • What steps to follow
  • What resources are available
  • What constraints matter

02 — WHAT ARE SKILLS

Skills, Tools & Frameworks

Tool

Exposes an action the agent can call. read_file, search_codebase

Skill

Packages reusable knowledge about how to do a task. "When reviewing PRs, check X, Y, Z"

Framework

Coordinates multiple agents, state, and control flow. LangGraph, OpenAI Agents SDK

Real-World Skill Examples

  • PR description generation
  • Code review checklists
  • TDD workflow enforcement
  • Debugging playbooks
  • Safety guardrails

02 — WHAT ARE SKILLS

Two Kinds of Skills

★

Domain Skills

What the agent needs to know

  • How to use a specific API correctly
  • Framework conventions & patterns
  • Document editing standards
  • Technical reference material
▶

Workflow Skills

How the agent should operate

  • Planning before coding
  • TDD workflow enforcement
  • Code review checklists
  • Debugging playbooks

Skills encode what to know or how to work. Often you need both.

03

SKILL.md & Progressive Disclosure

03 — PACKAGE ANATOMY

The Skill Package

A skill is a directory with a required main file and optional supporting folders.

my-skill/
├── SKILL.md # Main instruction (required)
├── references/ # Background docs, schemas
├── scripts/ # Deterministic helper code
└── assets/ # Templates, images, static

Front matter (YAML): name + description — these determine routing.

Body (Markdown): when to use it, steps, constraints, examples.

03 — PROGRESSIVE DISCLOSURE

Layered Loading

Agent context is limited. Skills give information in layers, only loading what's needed.

Layer 1 — Metadata

~100 tokens. name + description. Agent decides: does this apply?

Layer 2 — SKILL.md Body

~500 lines max. Full instructions, steps, constraints, examples.

Layer 3 — References / Scripts

Loaded on-demand only. Long schemas, API docs, helper scripts.

Key rule: If it's too long for the main file, put it in references/ and link to it.

03 — SKILL.MD TEMPLATE

SKILL.md Template

--- name: your-skill-name description: One sentence: what it does and when to use it --- ## When to use this skill [2-3 bullet points with concrete trigger conditions] ## Steps 1. [First step the agent should take] 2. [Second step] 3. [And so on...] ## Constraints - [What the agent should NOT do] - [Style or quality requirements] ## Examples **Input:** [What the user might ask] **Output:** [What good output looks like]

04

Authoring Workflow

04 — AUTHORING WORKFLOW

6 Steps to a Skill

  1. 1 Collect a concrete use case — what task repeats? What fragile steps go wrong?
  2. 2 Draft the SKILL.md core — name, description, essential instructions. Under 500 lines.
  3. 3 Move bulk to references — split long sections into references/.
  4. 4 Add scripts where determinism matters — exact logic, not LLM judgment.
  5. 5 Test — triggers on right inputs? Silent on wrong ones? Correct output?
  6. 6 Iterate — fix vague triggers, tighten constraints, add missing examples.

04 — AUTHORING WORKFLOW

Writing Good Descriptions

"Helps with code stuff"

Vague. No trigger. No concrete task. The agent won't know when to use this.

"Generate a structured PR description from git diff, including change summary, risk assessment, and test plan. Trigger when the user asks to write or generate a PR/commit description."

Concrete task, specific output, clear trigger keywords. The agent can match on this.

Common Mistakes

Vague triggers — "use this sometimes"

Oversized instructions — 2000+ lines in SKILL.md

Missing examples — no "here's what good looks like"

No scope boundary — when should the skill NOT apply?
