03 / 12 The Reframe

The reframe

Context IS the Agent

A good agent is a well-authored context — scope, procedures, feedback signals.
The model is the least interesting part.

04 / 12
01

Scope
Discipline

A good agent knows what it won't do. Scope without constraints is an agent that never stops.

Contrast

— without scope Help me with my code.
+ with scope Review PRs for security and correctness.
Do not refactor unless explicitly asked.
Stop after one pass.

The constraint is the feature. An agent that knows its boundary is more useful than one that tries everything.

05 / 12 Three Principles
02

Operating
Procedures

Without packaged procedures, the agent reinvents the task every time — differently.

What a skill encodes

— without a skill Same prompt. Different result every time.
Behavior depends on luck.
+ with a skill name: review-pr
trigger: user asks to review a PR
steps: [check scope, security, tests...]
do not: refactor, rewrite, opine on style

A skill is an SOP for an agent: when to use it, steps to follow, what to avoid. Consistency encoded — not left to chance.

06 / 12 Three Principles
03

Feedback
Loops

Good agents have signals that tell them when they're wrong. Most deployed agents have none.

The harness

Tests, lints, CI gates, reviewer agents — the harness surfaces the right signal at the right time.

Key insight: Don't front-load all instructions. Let the agent prototype — then enforce constraints at lint and test time, when the agent can see both the work and the requirements at once.

10 / 12

Where to start

Don't fix everything at once.
Write one skill.

01

Pick one recurring task your agent does inconsistently

02

Write a SKILL.md: name, trigger conditions, steps, one "do NOT"

03

Test it. Does it trigger when it should? Stay quiet when it shouldn't?

The best skills emerge from real usage, not theory.
