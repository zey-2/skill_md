02

Why Agent Skills

Problem

Agents Without Skills

Same task, different output every time. Agents hallucinate patterns, skip steps, invent conventions.

The Cost
  • Time wasted correcting agent output
  • No consistent team standards
  • Each session starts from zero
Solution

Skills = Reusable Operating Procedures

A skill tells the agent:

  • When to use it
  • What steps to follow
  • What resources are available
  • What constraints matter
Key Insight

Domain vs Workflow Skills

Domain: What the agent needs to know — API patterns, conventions, references

Workflow: How the agent should operate — TDD, code review, debugging

MCP gives agents new hands. Skills give them a brain for a specific job.

The Skill Package

SKILL.md

  • SKILL.md — Main instruction file (required)
  • references/ — Background docs, API schemas
  • scripts/ — Deterministic helper code
  • assets/ — Templates, images, static files

03 — FRONTMATTER

Frontmatter is Everything

name + description = the routing mechanism

The agent sees ONLY these fields to decide if the skill applies.

Description = triggering conditions ONLY

Not what the skill does. Not the workflow. Just WHEN to use it.

Start with "Use when..."

Third person. Under 500 characters. When descriptions summarize process, Claude skips the full skill content.

03 — PROGRESSIVE DISCLOSURE

Layered Loading

Layer 1
Metadata
Layer 2
SKILL.md Body
Layer 3
References
↓
↓
  • Layer 1: Metadata (~100 tokens) — name + description
  • Layer 2: SKILL.md Body (~500 lines) — instructions, steps, constraints
  • Layer 3: References (on-demand) — API docs, schemas, scripts

If it's too long for the main file, put it in references/ and link to it.

03 — TEMPLATE

SKILL.md Template

--- name: your-skill-name description: Use when [triggering conditions] --- ## When to use this skill [2-3 concrete trigger conditions] ## Steps 1. [First step the agent should take] 2. [Second step] ## Constraints - [What the agent should NOT do] - [Style or quality requirements] ## Examples **Input:** [What the user asks] **Output:** [What good output looks like]

04 — COMMON PATTERNS

What All 5 Approaches Agree On

Description = routing

name and description decide when to load

Progressive disclosure

3-tier loading: metadata → body → references

Examples > abstractions

One excellent example beats many mediocre ones

Test before deploy

Run the task without the skill first, watch it fail

Keep SKILL.md concise

Under 500 lines. Move bulk to references/

References one level deep

No nested references. Link directly from SKILL.md

06 — RISKS

Risks of Using Skills from Unknown Sources

Risks

Prompt Injection

Malicious SKILL.md with hidden instructions that override agent behavior

Supply Chain Risk

Installing skills from unverified authors or repositories

Data Exfiltration

Scripts that read and transmit sensitive files from your project

Over-Reliance

Trusting unverified skills with critical workflows without review

Defenses

Read Before Installing

Always review SKILL.md contents and scripts before adding a skill

Sandbox Execution

Run skills in isolated environments when possible

Trust Verified Sources

Prefer skills from known authors, official registries, or peer-reviewed repos

Principle of Least Surprise

A skill's contents should not surprise you in their intent
